# 招投标双向复核设计与追责边界

## 目标

把“DeepSeek 自己上网找一找”改造成一条可追溯、可失败、不自动放行的招投标公开信息复核链。

本 MCP 的责任是：

- 执行固定正向/逆向查询计划；
- 在授权官网范围内搜索和受控取页；
- 保留 query、URL、时间、哈希、后端、失败和覆盖缺口；
- 输出字段观察、带项目锚点的风险文本信号与强制人工闸门。

本 MCP 的责任**不是**：

- 证明搜索引擎没有漏收；
- 自动识别法律适用、主体角色、标包归属、金额口径或履约事实；
- 给出“通过”、“真实”、“合法”、“不存在风险”等结论；
- 替平台建长期防篡改审计库；
- 替实名复核人/审批人签字。

## 固定执行序列

```text
案件结构化输入
   ↓ 本地校验、运算符注入清理、原始/规范化输入哈希
F01 / F02 / F03 正向查询
   ↓ 冻结正向候选
R01 / R02 / R03 / R04 / R05 逆向查询
   ↓ 八条搜索全部完成后再取页；新逆向 URL 优先，同 URL 保留分阶段 provenance
   ↓ 全案件默认最多 10 次取页，未取唯一候选显式记缺口
字段观察 + 带项目锚点的风险信号 + coverage
   ↓
system_status + review_reasons + human_gate
   ↓
平台持久化 + 实名人工查原文 + 签核
```

| ID | 查什么 | 主要用来防什么 |
|---|---|---|
| F01 | 项目身份+中标/成交/结果 | 找不到基础结果链 |
| F02 | 项目+主体+标包 | 同名、串标包、角色混淆 |
| F03 | 合同+履约验收 | 把中标误当已履约 |
| R01 | 更正/变更/澄清 | 只看旧版公告 |
| R02 | 终止/中止/暂停/废标/流标/取消/撤销/撤回/作废/停止采购 | 已失效或停止仍被采信 |
| R03 | 质疑/投诉处理与决定/监督/结果无效 | 漏掉监管/救济线索 |
| R04 | 法定全称/信用代码反绑 | 简称、母子公司、曾用名混淆 |
| R05 | 后续合同/验收、合同解除/终止、验收不合格、重新采购/招标 | 只停在早期结果公告 |

## 模型不能跳过的边界

MCP 和 DeepSeek Function schema 不向模型暴露：

- `domains`；
- `max_results_per_query`；
- `max_pages_to_fetch`；
- 跳过逆向、自动通过或关闭人工闸门的开关。

模型无法用工具参数扩大域名授权、降低固定 3+5 流程或要求 `approved=true`。受信操作者在 service/CLI 内能收窄域名和调低预算，但这些不得转成模型控制面。

## 输出判读规则

### 证据状态

- `candidate_unverified`：搜索候选，未读原文；
- `retrieved_not_verified`：按 URL 取得了字节/片段并计算哈希，仍未核定事实。

### 字段观察

`observed_in_retrieved_excerpt` 只在同页绑定项目名+项目编号的完整可读页面上计算。编号、标包、金额、日期用对应边界规则；其他字段用 NFKC 规范化子串。仍不绑定语法主宾、主体角色或金额口径。机械覆盖完整还要求至少一页同时绑定申报标包、供应商法定名和信用代码，禁止跨标包、分公司或母子公司拼接。

### 风险信号

只有页面同时命中：

1. 更正/终止/投诉等风险词；
2. 当案件的项目编号或项目名称；

才输出 `TenderRiskSignal`，并保留 `matched_anchor_fields`。风险文本先做 NFKC/空白规范化，再用固定短语+受限模式捕捉插词变体。这只减少漏报/无关页误报，不证明风险公告必然针对同一标包/主体；还要人工核对上下文和时间线。

### 系统状态

`two_pass_completed_pending_human`、`risk_signals_found`、`inconclusive`、`no_candidate_observed`、`insufficient_identifiers`、`offline_fixture_only` 全部都不是业务通过。

`no_candidate_observed` 特意不叫 `not_found`，因为它只能说“本次搜索没观察到”，不能说事实不存在。

### 人工闸门

`manual_review_required=true`、`system_may_auto_approve=false`、`platform_must_record_reviewer_identity=true` 是不可由 DeepSeek 改写的服务端输出。

## 两条制度线不能混

### 政府采购

- [财政部令第 101 号《政府采购信息发布管理办法》](https://tfs.mof.gov.cn/caizhengbuling/201912/t20191210_3439068.htm)；
- [财政部令第 87 号《政府采购货物和服务招标投标管理办法》](https://www.mof.gov.cn/gp/xxgkml/tfs/201707/t20170718_2652766.htm)。

这条线需核对政府采购项目信息、中标/成交、合同、投诉/监督等，并按属地与当时有效规定判断指定发布媒介。

### 依法必须招标

- [国家发展改革委令第 10 号《招标公告和公示信息发布管理办法》](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=18519)。

这条线包含资格预审公告、招标公告、中标候选人公示、中标结果公示等。候选人不等于最终中标人，中标结果不等于履约。

当 `procurement_regime=unknown` 时，必须记为人工判断点，不得默认制度线。具体项目的法律适用与媒介优先级由当时的业务/法务人员确认，本文档不是法律意见。

## 责任分工

| 角色 | 必须负责 | 不得外包给模型 |
|---|---|---|
| 申请/操作人 | 提供并确认项目、编号、标包、主体、金额、日期和声称角色 | 让模型悄悄补编号/信用代码 |
| 平台宿主 | 每案件新建 service，确定性调工具，验 schema/deadline/finish_reason，保存原始输入输出 | 用 `tool_choice=auto` 赌流程执行 |
| MCP | 执行固定查询、网络安全、取页、哈希、缺口和人工闸门 | 输出 pass/法律结论 |
| DeepSeek | 辅助解读结构化台账，标明候选/缺口/待人工 | 篡改 URL/工具 JSON，自行审批 |
| 复核人 | 打开原文/附件，核对主体、标包、金额、公告类型、时间线和制度线 | 只看 DeepSeek 摘要便签字 |
| 审批人 | 基于取证台账+复核意见签核，对缺口决定补证/驳回 | 把 `ok=true` 当通过 |
| 运维/安全 | 密钥、SearXNG/Brave、egress、容量、限流、告警、版本和证据保留 | 为了可用性关闭 SSRF/robots/域名授权 |

## 平台长期审计要求

MCP 输出的 `run_id`、`server_version`、`workflow_version`、`raw_input_sha256`、`normalized_input_sha256`、`plan_sha256`、时间、URL 和正文哈希只是单次台账元素。平台还必须实现：

- 案件 ID/租户隔离，请求人、操作人、复核人、审批人实名与职责分离；
- 原始案件输入、工具输出 JSON、schema/工作流/MCP 版本；
- 模型 ID、API 请求 ID、`system_fingerprint`、`finish_reason`、tool call ID；
- 每次查询和抓取、失败、重试、超时、未取候选；
- 复核人查看哪些原文/附件、对哪些字段、为什么采信/不采信；
- 签核、修改、重开、追加取证和定期重跑逆向复查记录；
- 权限、防篡改、保留期、导出、删除和安全告警策略。

DeepSeek thinking 输出的 `reasoning_content` 是 API 调用运输状态，不是官方证据或审批理由。它在 tool call 上下文中需按 DeepSeek 官方要求完整回传；是否长期保留应遵循平台数据分类和保密策略。

## 上线前否决条件

任意一条未满足，不应宣称为政府项目自动复核链：

- 宿主还在用 `tool_choice=auto` 决定是否取证；
- UI 会把 `ok=true` 或 `two_pass_completed_pending_human` 显示为“通过”；
- `no_candidate_observed` 被翻译为“不存在”；
- PDF/动态页/robots/403/超时没有显示为证据缺口；
- 不同案件共用候选 URL 登记且无案件级隔离；
- 只存 DeepSeek 最终文本，不存原始工具 JSON；
- 无实名复核/审批人与签核时间；
- 日志或截图可泄露 DeepSeek/Brave key 或整页正文；
- 为了抓到页面而绕过 robots、验证码、登录或访问控制。
